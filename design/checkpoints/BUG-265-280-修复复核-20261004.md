## 可复现问题

### 1. P1 · BUG-281：未保存编辑仍可直接确认服务端旧值

定位：`frontend/src/views/BatchIntakeView.vue:254-266`，以及 `syncEdits` 的 200-206 行。

复现：打开服务端候选《活着》、副题 null → 输入框改为《许三观卖血记》、副题“正确副题” → 不点保存，勾选并点击确认。

实际结果：确认请求只有 `candidate_ids: [11]`，没有任何 PATCH。服务端被确认的仍是《活着》/null；页面刷新后，因为服务端指纹未改变，继续保留《许三观卖血记》/“正确副题”的草稿，并提示“已确认 1 条”。执行使用服务端旧值。

BUG-273 的服务端内容变化缓存刷新已经有效，但未保存修改的确认入口仍存在“所见非所存”。BUG-275 增加了副题编辑入口，也受此影响。确认前需要保存编辑或明确阻止未保存候选进入确认，不能继续显示成功。

验证：临时 vitest 探针渲染真实 Vue 组件、修改两个输入框、触发真实确认事件，检查 fetch 调用与刷新后界面；已复现。现有测试仅分别覆盖保存、确认和快照刷新，未覆盖未保存编辑直接确认。

### 2. P2 · BUG-265：上传失败清理未覆盖部分写入和数据库提交失败

定位：`backend/app/services/intake_workflow.py:179-180` 和第 198 行。

两个独立失败点：

1. `write_bytes` 写出一部分字节后抛 OSError 时，文件尚未加入 `written`。上传两张照片，第二张写出 `uv` 后模拟磁盘满；数据库照片记录为 0，第一张已清理，第二张 `p0002.jpg` 仍存在，内容为 `uv`。
2. `db.commit()` 位于清理的 try/except 外。模拟提交失败并回滚后，数据库照片记录为 0，但上传文件仍在。

路径白名单和 containment 校验未发现绕过。此处残留是清理完整性问题，不是路径穿越仍可利用。清理范围需要涵盖正在写入的文件和数据库提交失败，并确保回滚不会被清理异常跳过。

现有回归测试在第二次写入开始前直接抛异常，未模拟已经产生部分文件；也未覆盖提交失败。

### 3. P2 · BUG-276：自动推断确认字段仍把显式清空当作未提供

定位：`backend/app/services/intake.py:483-486`；`backend/app/schemas/intake.py:52` 的作者清洗会进一步丢失空数组信息。

复现：传 `field_policy='prefer_confirmed'`、`subtitle=''`、`authors=[]`，省略 `confirmed_fields`，外部元数据返回“外部副题”与“外部作者”。

实际结果：`_confirmed_field_names` 仅推断出 title/isbn，没有 subtitle/authors；最终保存了外部副题和外部作者。

该函数契约明确“未显式提供列表时，所有已提供的输入字段视为确认”；契约基线 §5 明确“清空字段不可被再次补回”。因此显式空值不应被非空判断排除。JSON 请求作者清洗把 `[]` 变成 None，也需要保留未提供与显式清空的区别。

显式传 `confirmed_fields=['subtitle', 'authors']` 的分支已修，工作流通过生成确认列表也已修。现有空值回归全部显式提供确认列表，未覆盖自动推断分支；非空作者自动推断已有测试。

### 4. P2 · BUG-282：软删除候选仍能重新确认并实际入库

定位：`backend/app/services/intake_workflow.py:659-663`；前端 `BatchIntakeView.vue:380-386`。

复现：构建候选甲 → 确认 → 编辑为“编辑后甲” → 重新构建“重建后乙”。旧甲因历史引用被标记 rejected，新乙为 pending_review。再次选中旧甲确认并执行。

实际结果：成功建立《编辑后甲》，新乙仍 pending_review，任务 partial。

后端没有拒绝 rejected 候选，前端既展示这些追溯行又允许勾选（只禁用 executed）。因此普通工作台操作即可触发，软删除未使旧结果退出后续流程。应明确拒绝旧候选确认，并让界面将追溯记录与当前可操作候选区分。

原 BUG-268 的外键 500 已解决；本问题是软删除方案产生的生命周期遗漏。旧版本命令的参数摘要校验及完成汇总版本过滤未发现同路径失效。

### 5. P2 · BUG-283：重试成功后批次仍显示 failed/partial

定位：`backend/app/services/intake_workflow.py:1179`；前端执行按钮在 `BatchIntakeView.vue:367`。

复现：只有一个已确认候选；首次执行模拟临时异常，任务与命令均 failed；恢复依赖后调用单命令 retry。

实际结果：命令 completed、候选 executed，但任务仍 failed。retry 直接返回单命令执行结果，未重算所属任务完成状态。

前端重试后仅刷新快照，执行按钮仅允许 confirmed，无法用该按钮立即纠正汇总状态。重新发起整批 execute API 可以重算，但正常重试成功应自动同步状态，并沿用 BUG-267/274 的当前版本及待核对候选判定。

现有重试测试验证失败继续失败和完成命令幂等返回，未验证失败后真正成功时任务的汇总状态。
