   提示"Owner 在 /llm-settings 启用后再评测"，零 API 调用。

   失败分布、费用 `null/unknown`（不填 0）、样本统计 6 照片/5 本书（同组照片正确合并）。
3. 回归：`tests/scripts` 118 项、`backend/tests` 全量通过（见台账 DEV 条目）。

## BI-11 / PLN-011 结论（当前）

**状态：工具就绪，真实评测 no-go（等待 Owner 模型配置）。**

- 本机后端库未配置识书模型（`llm_settings` 无启用行）；真实评测需要 Owner 在
  `/llm-settings` 配置 OpenAI 兼容接口（地址/模型 ID/API Key）并承担外部 API 费用，
  这不在本次开发会话可决定范围。
- 真实金标准亦待人工核对：user-set 现有 6 张合成照片（5 本书）全部 `verified: false`，
  且低于 20 本下限——即使模型配置好，`--yes` 门控在真实金标准补齐并逐项核对前
  不会放行（这正是门控的设计行为）。
- **待 Owner 完成后的操作序列**（go 决策路径）：
  1. `/llm-settings` 启用模型；
  2. 放入真实封面并人工标注（含 `group`/`verified`/`isbn_visible`），
     核对量 ≥ 20 本不同书（含关键困难类别）；
  3. `backend/.venv/bin/python scripts/run_cover_model_eval.py --golden tests/eval/user-set/golden.json --database-url <后端库>`；
  4. 按报告六项指标 + 分档 + 失败分布给出 go/no-go（不以识别成功率替代正确率；
     任何误合并/静默覆盖类失败单独阻断）。
- 评测不修改图书库已由实现保证（运行器只 SELECT llm_settings，识别仅产候选）。

## 权限与安全说明

- 运行器是受信任本机运维入口：显式 `--database-url`，不新增远程 Agent 权限；
  API Key 只在服务内部使用，报告仅含模型 ID、指纹与接口主机名（剥离 userinfo）。
- 视觉服务只生成候选，不触碰图书写入路径（模型不得直接调用图书写入，规划 §4.6）。
- Web 发起的完整批次识别仍按规划留在 M3 工作台，未提前引入。

## 剩余限制

1. `_post_chat_completion` 基于同步 httpx；M3 工作台接入 API 时如需异步可另行包装（行为已由测试钉住）。
2. 缓存不设 TTL（按指纹失效）；换 Key/配置即失效，图片变更即失效，满足当前口径。
3. 合成集（tests/eval/golden.json）未迁移 v2 字段——compare 兼容读取，运行器对合成集
   统计的 verified_groups 恒为 0，合成集不能用于 `--yes` 门控（符合"真实金标准"要求）。
