## LOC-01 产品语义冻结

| 项 | 冻结结论 |
| --- | --- |
| 格子布局 | 每层格子数可不同；编号约定「面向书架正面，层从上到下、格子从左到右」，界面固定展示该约定 |
| 成员权限 | 第一阶段 Member 只读位置；所有结构化位置写操作仅 Owner Web 会话（含现有 CSRF），不向 Member/Token 开放 |
| 照片可见范围 | 登录家庭成员（Owner/Member Web）可读；匿名共享目录与现有 MCP 目录工具不提供精确位置与书架照片 |
| 照片圈选 | 第一期不做照片区域标注；用独立层格示意图高亮定位 |
| 副本默认数量 | 不自动创建实体副本；不按书目数、照片数推定册数；每项由人工确认实际册数与归属成员 |
| 上限默认值 | 每架照片 ≤5 张；单张 ≤10 MiB、解码像素 ≤2000 万；批量移动/补录每批 ≤100 册；超出拒绝 |
| 定位粒度 | 仅到书架与到格子均允许；仅到书架显示「格子待登记」；两者皆无显示未定位 |
| PLN-013 衔接 | 存量 76 个书目**不**自动补建副本；「副本与位置补录」流程先列已有副本分配位置，用户显式确认增购册数时才新增。PLN-013 保持待办，待实际补录完成后收口 |

## LOC-02 API 与契约冻结

- 端点集以设计文档第 9 节为准（`/api/v1/storage/...` + `PATCH /books/{book_id}/copies/{copy_id}/placement`），不再增减；响应沿用项目 ApiResponse 包装，清单全部分页。
- 新增 Scope：`locations:read`（读位置结构/副本位置），照片内容读取须同时具备 `files:read`。写入不新增 Token Scope——第一阶段结构化写仅 Owner Web。`locations:read` 加入服务器角色能力表（Owner/Member 可读）、Agent 可授予集合、发现契约与授权矩阵；**不向已有 Token 自动追加**。
- 幂等：非幂等创建与批量写必须传 `idempotency_key`；同 key 同摘要重放返回原回执，同 key 不同摘要 409 `IDEMPOTENCY_CONFLICT`；写事务开始即登记 key 并与业务修改同事务提交；并发同 key 等待首事务完成后读回执。
- 回执查询：`GET /storage/operations/{idempotency_key}` 区分 completed 与 not_found；not_found 不得解释为「确定未执行」，客户端等待重查或同 key 同摘要重放，不换新 key。
- 版本与冲突：所有变更传期望版本；错误码冻结为 `PLACEMENT_CHANGED`、`LOCATION_ARCHIVED`、`LOCATION_IN_USE`（409）、`IDEMPOTENCY_CONFLICT`（409）、非法层格关系 422、图片超限 413、未授权 401/403、不存在 404。

### 契约修订记录（实施期回写）

- 2026-10-06（LOC-06）：新增错误码 `CODE_CONFLICT`（409），用于 room/shelf code 全局唯一与 cell code 架内不复用的唯一性冲突——冻结表原未覆盖唯一约束竞争；服务层预检 + 提交时 `IntegrityError` 兜底统一映射。
- 2026-10-06（LOC-06）：PATCH（改名/排序/归档/恢复）的 `idempotency_key` 可选——期望版本天然防重；带 key 时同样登记回执。POST 创建与 PUT 布局仍为必传。
- 2026-10-06（LOC-06）：`PUT /storage/shelves/{id}/layout` 采用全量表达语义——未列出的现存活动层/格视为归档请求（有引用则 409 LOCATION_IN_USE）；层的 `cells` 键缺省表示不动该层格子。该语义直接落实「合并/拆分先明确处理引用」并防止删重建绕过。
- 2026-10-06（LOC-06）：创建书架不 bump 所属房间版本，避免房间版本随子资源增删漂移、干扰房间自身的期望版本语义。
- 2026-10-06（LOC-08）：归档节点上的副本位置路径展示口径——设计文档无明文，取「保留展示完整路径，归档节点名称后标注（已归档）」（归档本身已被引用检查阻断，该路径只出现在历史/直写数据上）。
- 2026-10-06（LOC-08）：`GET /storage/unlocated` 响应形状——三类清单（copies_without_placement / legacy_location_only / books_without_physical_copy）以三桶结构同响应返回，各自带 items+total，共用 limit/offset；不加 category 参数，避免三类被分开请求时口径漂移。
- 2026-10-06（LOC-08）：数量统计挂载位置——端点集冻结不新增路由，统计以附加字段并入既有端点：房间清单每项 `stats`、书架详情 `stats`（§9 明文要求书架详情含统计）；字段为 §6.3 四值 assigned_copies/present_copies/on_shelf_copies/books_involved。
- 旧客户端兼容：副本响应新增 `placement` 对象与 `location_display`（无结构化定位时回退旧 `location` 文字）；旧 `location` 字段保留可读；旧客户端向已结构化定位副本写 `location` 返回 409；旧 MCP 目录输出契约不漂移。
- 2026-10-07（BUG-298，LOC-05/13/15）：有 `locations:read` 的副本响应另含独立 `placement_version`，首次未定位与清除后均返回数据库真实版本，已定位时与 `placement.version` 一致；保留 `placement=null` 的未定位语义。无该权限的响应完全不含 `placement`、`placement_version`、`location_display`。编辑器优先使用独立版本，兼容旧已定位响应中的 `placement.version`；缺版本时提示刷新，不推断为 1。
- 2026-10-06（LOC-09）：照片域新增错误码——`INVALID_IMAGE`（422，真实解码失败或格式非 JPEG/PNG/WebP，含伪扩展名）、`PHOTO_TOO_LARGE`（413，字节 >10MiB 或解码像素 >2000 万；字节超限由上传读取层统一映射为同一结构化错误）、`PHOTO_LIMIT_EXCEEDED`（422，每架 >5 张）。
- 2026-10-06（LOC-09）：端点集出入——§9 无明文照片清单端点，按「清单全部分页」纪律新增 `GET /storage/shelves/{id}/photos`（locations:read）；`GET /storage/shelves/{id}` 详情新增 `photos` 字段（受授权的照片引用，落实 §9 明文）。
- 2026-10-06（LOC-09）：`DELETE /storage/photos/{id}` 的期望版本与可选幂等 key 走 query 参数（DELETE 不带请求体）。
- 2026-10-06（LOC-09）：架内首张照片无论请求值一律成为主图（保证「每架最多一张主图」之外的可用默认：有照片的架始终有主图）；显式设主图在同一事务内清同架其他主图，配合部分唯一索引兜底并发。
- 2026-10-06（LOC-09）：文件回收入口——进程启动（lifespan `resume_gc_jobs`）+ 删除 commit 后即时 best-effort 处理；孤儿核对为只读服务函数 `orphan_audit`（>24h 无引用才列入，供人工确认），不暴露 HTTP 端点、不自动删除。
- 2026-10-06（LOC-13）：位置域新增错误码——`INVALID_BATCH`（422，批次形状违规：空批、>100 册上限、批次内 copy_id 重复）、`INVALID_COPY_TYPE`（422，电子副本登记实体位置；DB 的 ck_book_copies_placement_physical 约束兜底）、`LEGACY_LOCATION_WRITE`（409，placement 端点携带旧 `location` 文字字段一律拒绝；对已结构化定位副本落实冻结条文「旧客户端写 location 返回 409 并引导使用位置接口」——现存 API 无副本更新端点，旧文字唯一写入口是创建副本，故守卫落在 placement 端点）。
- 2026-10-06（LOC-13）：清除位置语义——`PATCH .../placement` 的 `target=null` 表示清除，此时必须显式 `keep_legacy_location`（true 保留 / false 清空旧 `location` 文字），缺省 422；设置/移动时该字段不得出现（422）。
- 2026-10-06（LOC-13）：`preview_digest` 口径——对规范化意图载荷 `{target:{shelf_id,cell_id,shelf_version,cell_version}, copies:[{copy_id,placement_version}]（按 copy_id 升序）}` 取 storage_tx.payload_digest；预览按当前状态填充版本并返回摘要，执行按请求体重算比对，不符 409 `PLACEMENT_CHANGED`。
- 2026-10-06（LOC-13）：批量移动仅支持同一非空目标（到书架或到格子）；批量清除不开放——清除须逐册走单册端点，以逐册明确 keep_legacy_location。
- 2026-10-06（LOC-13）：单册 PATCH 的 `idempotency_key` 可选（沿用 LOC-06 修订：期望版本天然防重，带 key 同样登记回执）；批量执行 POST 必传；预览为 dry-run 不落库、不登记幂等键。
- 2026-10-06（LOC-13）：源位置归档不阻断移出（归档时的引用检查已保证 API 路径下不会出现「已归档仍有引用」，移出属历史/直写数据清理）；目标链任一节点（房间/书架/层/格）归档一律 409 `LOCATION_ARCHIVED`。
- 2026-10-06（LOC-14）：`POST /storage/copies` 请求形状（冻结 §9 只列端点未给载荷）——`{idempotency_key, items:[{book_id, assign:[{copy_id, placement_version, target}], new_copies:{count, owner_member_id, target}}]}`；每项 assign/new_copies 至少其一（422）；批次内 book_id 不重复（同一书目的分配与新增合并为一条目）；≤100 册冻结上限的口径 = 全请求 assign 条数与新增册数合计，超出 422 `INVALID_BATCH`。
- 2026-10-06（LOC-14）：不新增补录预览端点——已有副本清单与 placement_version 由既读接口（书目详情、`GET /storage/unlocated`）提供，「整体预览」（§9 多目标补录注）由补录页面客户端侧组装（LOC-16）；执行端点自身原子重验目标与全部期望版本。
- 2026-10-06（LOC-14）：新增副本字段面仅 册数/归属成员/初始位置——copy_type 固定 physical、status 默认 in_shelf、旧 location 文字留空；format/condition/acquire_type 等其余属性不在补录契约内，后续以副本编辑能力补充。成员校验 = 存在（404 NOT_FOUND），不对 disabled 成员加额外限制（本期不扩展）。
- 2026-10-06（LOC-14）：事务纪律落实——不复用会自行 commit 的 `create_copy`，补录在 storage_intake 内直接构造 BookCopy；副本创建、位置设置、幂等回执、审计（`storage.copies.intake`，payload 含各条目原/新位置 ID 与展示路径快照）单事务提交；旧 `POST /books/{id}/copies` 提交语义不变。

## LOC-03 技术约束冻结

- 关系约束：`shelf_cells` 与 `BookCopy.placement` 使用（shelf_id, cell_id）复合外键保证层格同属一个书架；SQLite 启用 `PRAGMA foreign_keys=ON`；编号 code 仅作可读标签，不作关联键；cell code 书架内唯一且不复用。
- 锁顺序：写事务先收集源与目标位置的完整祖先集合，按 room → shelf → layer → cell → copy 类型顺序、类内按 ID 升序加锁；SQLite 用条件 UPDATE 取写锁并重读，PostgreSQL 用同等资源锁策略；锁定后重验父子关系、版本与祖先集合，不符即回滚，不持锁补锁；忙/死锁仅在确定整体回滚后从头重试 ≤3 次，版本冲突不重试。
- 事务边界：位置服务不复用会自行 commit 的 `create_copy`；提取由调用方控制事务的领域操作，保留旧 API 提交语义；业务修改、幂等回执、OperationLog 审计同事务提交；审计失败则整个位置事务失败，不用 `log_and_commit`。
- 照片生命周期：上传先写暂存文件，数据库失败仅清理本次文件；格式 JPEG/PNG/WebP，服务端验证真实格式与尺寸，解码重编码并去 EXIF；删除/替换在同事务登记 `location_file_gc_jobs`，commit 后清理旧文件，进程中断后由下次启动或受控清理继续；回收任务用条件更新取短期租约，执行前重验路径 containment 与无引用；孤儿核对只读清单、保守筛选（>24h 无引用）人工确认后回收，不扫描 covers/attachments。
- 迁移与回退：Alembic 增量迁移建新表 + BookCopy 可空 placement 字段；旧行默认未定位；回退应用代码保留新表新列；不直接 drop 含数据新表。
- 部署验证：迁移先在现有数据库副本演练（核对 books/copies/进度/购买/笔记数量与引用）；SQLite 全量自动化验证；PostgreSQL 并发验证依赖环境可用性，本机无 PostgreSQL 时如实记录为未验证项，不标记通过。
