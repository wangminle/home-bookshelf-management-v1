## 2. BUG-298：清除位置后无法重新定位

触发路径：新副本位置版本 1 → 设置位置后版本 2 → 清除位置后版本 3 → 刷新详情 → 再设置位置。

- [serializers.py](../../backend/app/utils/serializers.py) 仅在 `placement_shelf_id` 非空时构造带 version 的 placement；清除后向已授权主体返回 `placement=null`，没有该副本的真实位置版本。
- [CopyPlacementEditor.vue](../../frontend/src/components/CopyPlacementEditor.vue) 取 `copy.placement?.version ?? 1`，因此刷新后仍用版本 1。
- 独立临时 SQLite 探针实际调用位置服务与详情使用的序列化函数：数据库版本为 3、响应 placement 为 null、编辑器载荷版本为 1，再设置返回 **409 PLACEMENT_CHANGED**。

刷新无法解决此冲突，因为接口仍不返回真实版本。需要统一已授权主体的未定位副本版本契约并同步前端；无位置权限主体的字段隔离须保持。回归应覆盖“设置 → 清除 → 刷新 → 再设置”，不能只验证服务调用者手动传正确版本。

已登记 BUG-298 为待修复；本轮没有修复该问题。

## 5. BUG-298 修复与回归（2026-10-07）

副本响应向有 `locations:read` 的主体返回独立 `placement_version`，即使 `placement=null` 仍保留真实版本；已定位时该值与 `placement.version` 一致。未授权响应继续完全隐藏所有位置字段，Owner、Member 与 Agent 读取分别由权限回归覆盖，旧 MCP 目录字段集保持不变。

位置编辑器优先读取独立版本，兼容旧已定位响应中的 `placement.version`；缺少有效版本时提示刷新并通知父组件重载，不再猜测版本 1。无需增加数据库列或迁移。
