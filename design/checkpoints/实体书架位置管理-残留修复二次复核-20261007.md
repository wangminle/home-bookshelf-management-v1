## 2. 两条仍需修复的路径

### R1［P1／BUG-299］HTTP 成功但回执无法解析时，提前删除重试键

定位：[storage.ts](../../frontend/src/stores/storage.ts) 第 50～58 行，以及 [CopyProvisionForm.vue](../../frontend/src/components/CopyProvisionForm.vue) 第 46～51 行。

`request()` 捕获 json 解析失败并返回空对象，但 HTTP 201 且 body.ok 未显式为 false 时仍返回 body.data，即 undefined。补录组件收到这个值后先调用 forgetProvisionIdempotencyKey，再访问 result.created；后者抛 TypeError，被作为补录失败展示。

独立真实组件探针让模拟服务端按 key 接受补录、HTTP 返回 201，但 json() 因截断抛 SyntaxError。第一次显示 `Cannot read properties of undefined (reading 'created')`；相同 items 再提交时 key 已改变，模型计数从 1 册增加到 2 册。这里的两册是保留回执的模拟后端结果，不是访问真实家庭数据库的结果；业务服务对新 key 按新操作执行的契约未变。

因此“只有成功回执到达后才丢 key”的约束还未成立。必须把无法解析、空 data 或无效回执视为结果未确认，并保留 key；确认回执满足契约后再删除 key。不能单凭 HTTP 成功判断业务回执可用。建议正式回归覆盖网络异常与 HTTP 201／200 的 JSON 截断、空 data 两种边界。

### R2［P2／BUG-305］409 后刷新失败，仍宣告已刷新并允许旧版本重试

定位：[StorageView.vue](../../frontend/src/views/StorageView.vue) 第 94～129 行。

`loadAll()` 捕获读取异常、设置错误，但不向调用者返回失败或抛异常；`handleError(PLACEMENT_CHANGED)` 等到这个已失败的调用返回后，仍执行 syncOpenForms 并无条件写“已为你刷新最新数据”。此时 roomForm／shelfForm 可能仍是旧对象，版本并未更新。

独立组件场景：先加载房间 version=1；PATCH 返回 409；后续 GET rooms 断网。最终消息仍为“已为你刷新最新数据”，输入恢复可编辑；再次保存，捕获到两次 PATCH version 都是 1，持续冲突。

建议让刷新结果显式传播到冲突处理；失败时保留草稿、显示刷新失败并提供重载入口，不宣告已刷新，也不以旧版本继续执行同一次重试。只有成功获取最新对象后再进入核对与保存状态。
