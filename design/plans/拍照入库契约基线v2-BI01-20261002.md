## 2. 警告码（warnings）

后端 `IntakeOut.warnings[]` 与清单条目 `warnings[]`、run 报告共用同一套码。警告对象结构：

```json
{"code": "<警告码>", "message": "<人读消息>", "field": "<字段名|null>", "detail": {<可选证据，如确认值/元数据值/来源>}}
```

| 警告码 | 语义 | 产生环节 |
| --- | --- | --- |
| `barcode_dependency_unavailable` | 后端缺少 pyzbar/zbar，条码解码依赖不可用 | BI-02 |
| `barcode_decode_timeout` | 条码解码超时（默认 15s）被放弃 | BI-02 |
| `barcode_not_found` | 正常解码但图中未发现 ISBN 条码 | BI-02 |
| `barcode_invalid_checksum` | 解码结果校验位无效被丢弃 | BI-02 |
| `metadata_missing` | 外部元数据全部未命中（含网络故障导致的未命中） | BI-02 |
| `metadata_field_conflict` | 外部元数据与确认值冲突，已保留确认值（field + detail 记录双方值与来源） | BI-03 |
| `isbn_ownership_conflict` | ISBN 命中已有书但书名/作者明显冲突（阻断型，见 §5） | BI-03 |

兼容约束：`warnings` 为可选字段，未发生时响应中为空数组或缺失，旧客户端可忽略。

## 3. 错误码（error_code）

清单 `result.error_code` 与 run 报告 `entries[].error_code` 共用；`classify_client_error()` 按 `cli/bookshelf/client.py` 的消息格式稳定映射。

| 错误码 | 来源 |
| --- | --- |
| `missing_input` | 预检：缺 isbn 且缺 title |
| `file_missing` | 预检：封面文件缺失 |
| `invalid_isbn` | 手工 ISBN 位数/校验位错误（400） |
| `image_corrupted` | 图片损坏/无法读取（400，不以降级掩盖） |
| `barcode_dependency_unavailable` | 识别入口 503 且消息含 pyzbar/zbar |
| `isbn_ownership_conflict` | ISBN 归属冲突（BI-03 引入的 400） |
| `bad_request` / `conflict` / `unauthorized` / `forbidden` / `service_unavailable` | 其余 400/409/401/403/503 |
| `timeout` | “连接 API 超时”——**结果未知**，见 §7 |
| `network_error` | 连接失败 / 非 JSON（请求确定未受理，可重试） |
| `unknown` | 无法归类（兜底） |

## 4. manifest v2 字段（冻结）

顶层（v1 键全保留）：

```json
{
  "version": 2,
  "batch_id": "batch-<YYYYmmdd-HHMMSS>-<4hex>",     // 首次写出 v2 时固化，此后不变
  "source_dir": "/abs/path",
  "created_at": "…", "updated_at": "…",
  "entries": [ … ]
}
```

条目（v1 的 12 个键全保留，新增 6 个；顺序即写出顺序）：

| 新增键 | 类型/缺省 | 语义 |
| --- | --- | --- |
| `photo_id` | `"p0001"` 递增字符串 | 稳定照片 ID；scan 分配，合并沿用，序号延续清单内最大值。照片不是图书计数单位 |
| `sha256` | hex/null | 照片内容哈希，scan 时固化。只证明照片相同，不能据此判定两照片同一本书 |
| `role` | `cover`/`barcode`/`other`/`unknown`，scan 默认 `cover` | 图片角色 |
| `confirmed_fields` | `[]` | 用户核对过的字段名列表（BI-03 `prefer_confirmed` 输入） |
| `warnings` | `[]` | 条目级警告（§2 结构） |
| `candidate_id` | null | M3 候选书目预留 |

v2 `result` 结构（v1 的 `outcome/book_id/action/message/error` 保留，新增）：

```json
{
  "outcome": "created|exists|failed|outcome_unknown",
  "book_id": 18, "action": "…", "message": "…",
  "run_id": "run-<YYYYmmdd-HHMMSS>-<4hex>",   // BI-04：产生该结果的运行
  "at": "<iso8601>",                            // BI-04：结果时间
  "error_code": "<§3 错误码|null>",             // failed/outcome_unknown 必填
  "error": "<原始消息|null>",
  "warnings": [ … ]                             // 后端响应携带的警告（BI-02/03）
}
```

### 4.1 版本兼容约束（冻结）

- 读：支持 version 1 与 2；version 缺失按 1。version 大于支持范围 → 明确报错退出，**绝不写回**（防止未知字段被静默丢弃）。
- 写：总是写 version 2。磁盘上仍是 v1 的清单首次升级保存前，原文件备份为 `<name>.v1.bak`（已存在则不覆盖，保留最早原件）。
- 迁移不丢弃历史 result：v1 条目的 `result` 原样保留，仅补条目级缺省键。
- `photo_id` 补齐按清单内既有顺序分配，v1 文件在未写回前逐字节不变。

### 4.2 状态机（v2 新增 outcome_unknown）

`pending → recognized → confirmed / skip →（run）imported / failed / outcome_unknown`

- `failed`：确定失败（请求确定未受理或被 4xx/5xx 明确拒绝），可经 `--retry-failed` 重试。
- `outcome_unknown`：请求已发出但回执丢失（读超时等）。**不得被任何自动重试包含**；经人工核对或 reconcile 决定后，可用显式 `--retry-unknown`（BI-04）重发。

## 5. 字段策略（冻结）

请求（multipart 表单与 JSON 同名）新增可选：

- `field_policy`: `"default" | "prefer_confirmed"`，缺省 `default`。
- `confirmed_fields`: 字段名数组，缺省空。批量脚本对已确认条目显式传 `prefer_confirmed`。

优先级（`prefer_confirmed` 时）：**用户确认/编辑值 → 经核验识别候选 → 外部元数据补空**。模型置信度只用于排序提示，不能单独表示“经核验”；本阶段“经核验”即人工确认。

- `default`：保持既有行为（元数据可改写展示字段），旧客户端零改动兼容。
- `prefer_confirmed`：确认字段不被外部元数据覆盖；不一致时保留确认值并追加 `metadata_field_conflict` 警告（field + 双方值 + 来源）。
- 多作者：`authors` 数组端到端保留；`author` 单字符串仅作兼容输入。
- ISBN 校验位正确只证明格式成立，不代表归属该封面。**ISBN 归属冲突**（ISBN 键命中已有书且输入书名/作者与其明显冲突）→ 400 阻断 + `isbn_ownership_conflict`，不自动更新、不绑定、进入人工核对。
- 显式空值、字段未提供、自动补空三者分别定义；“清空字段”不可被再次补回。

## 6. 报告口径（冻结）

| 口径 | 定义 | 落点 |
| --- | --- | --- |
| 照片总数 `photos_total` | 批次内照片条目数（含重复与跳过） | run 报告顶层 |
| 单次运行 | 本次 created / exists / failed / outcome_unknown / skipped；重跑不抹去旧报告（报告文件名含 run 时间戳） | run 报告 `summary` |
| 最终关联 | 成功关联照片数、不同有效 book_id 数、未解决关联数 | reconcile 报告（BI-05） |
| 批次净新增 | 本批创建且最终仍存活的图书数；关联到原有图书不算新增 | reconcile 报告（BI-05） |
| 清理/修正 | 临时创建后删除、重映射、字段修正分别统计，不归为新入库成功 | reconcile 报告（BI-05） |

口径样例（20260930 批）：71 张照片 → 67 个最终图书；历史曾创建 70 条后删 3 条；另有 1 次重复封面命中已有书。不得累加重跑 created 得批次新增。

## 7. 结果未知（M1 边界，显式记录的限制）

`timeout`（连接 API 超时）与其他错误的本质区别：请求可能已被服务端受理，仅回执丢失。M1 约束：

1. 该条目标 `outcome_unknown`，不并入 `failed`；
2. `--retry-failed` 不包含它；重发须经人工核对后显式 `--retry-unknown`；
3. M1 仅有书名去重，不承诺副本/购买记录恰好一次；`outcome_unknown` 条目若已实际入库，重发会命中去重（action=exists）而非重复建书——但副本/购买记录可能重复，此边界记录在案，M3 由 CommandExecution 幂等键消除。

## 8. RES-006 元数据链实测结论（2026-10-02，本机网络）

工具：`scripts/diagnose_metadata_chain.py`；原始数据：[RES-006-metadata-diagnosis-20261002.json](../checkpoints/RES-006-metadata-diagnosis-20261002.json)。

| 探针 | nlc | google_books | openlibrary | 链级 |
| --- | --- | --- | --- | --- |
| 三体·ISBN | timeout(15s) | rate_limited(429) | ok → 三体 | ok（10.2s） |
| 活着·ISBN | timeout(15s) | rate_limited(429) | ok → 活着 | ok（9.5s） |
| 翦商·书名 | timeout(15s) | rate_limited(429) | ok → 翦商：殷周之变与华夏新生 | ok（2.5s） |
| 小学问·书名 | timeout(15s) | rate_limited(429) | no_result | no_result（8.0s） |
| 节气手帖·书名 | timeout(15s) | rate_limited(429) | no_result | no_result（8.0s） |

结论（对 OPT-013/014/015、RES-006 的修订依据）：

1. **`source=manual` 不能证明“外部无此书”**：本轮 nlc 5/5 网络超时、google_books 5/5 限流（无 API Key 配额）。67 本新增书 source 分布（64 manual / 3 openlibrary）中相当部分 manual 应归因于外部请求故障而非真无结果。
2. **链级耗时结构**：ISBN 探针链级 9.5～10.2s（primary 批 8s 超时 + openlibrary 兜底 ~1.5s），逼近 12s 总限；书名检索 no_result 用满 ~8s 批超时。入库慢的主因是 nlc 超时占用批次窗口。
3. **覆盖事实**：openlibrary 对《三体》《活着》《翦商》书名检索可返回正确中文书目（含副题完整书名）；《小学问》《节气手帖》真无结果。原批次“翦商被 Revelation 覆盖”属特定查询路径的错误元数据，openlibrary 直查本轮未复现。
4. **处置建议**（另行评估，不在本期实施）：配置 Google Books API Key 消除 429；诊断 nlc 网络路径（代理/防火墙）；`metadata_missing` 警告在 BI-02 中如实区分“未命中”与“依赖故障”（后者经 http 观察钩子可判）。
