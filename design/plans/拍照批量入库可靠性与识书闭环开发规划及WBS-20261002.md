# 拍照批量入库可靠性与识书闭环开发规划及 WBS

> 日期：2026-10-02；状态：规划稿，尚未实施。
> 执行说明：实施时使用 `executing-plans` 技能逐项执行；各工作包先补行为测试，再实现和验收。依项目 AGENTS.md，不自行执行 Git 提交或推送。

**目标：** 建立照片可追溯、字段可核对、中断可恢复、质量可评测的家庭图书入库流程。

**架构：** 第一阶段增强既有 Agent + CLI 入库路径；第二阶段复用后台模型配置建立统一视觉识别服务和真实评测；第三阶段将候选书目、确认与执行状态持久化，提供 Web 批量核对工作台。书目写入继续经过领域服务与既有授权校验。

**技术栈：** Python、FastAPI、SQLAlchemy、Alembic、Pillow/pyzbar、现有 HTTP 客户端、Vue 3、TypeScript、Pinia、pytest、Vitest。

## 2. 范围与产品目标

### 2.1 本期范围

1. 条码能力预检、有文字线索时降级、结构化警告。
2. 确认字段优先、元数据冲突可见、ISBN 归属冲突阻断。
3. 每条执行结果及时保存、运行历史保留、最终书目关联核对。
4. 统一视觉识别服务、真实金标准、可复现评测及自动模式门控。
5. 多图候选书目、重复候选预览、版本化确认及幂等执行。
6. Owner Web 批量核对、失败重试和阶段验收。

### 2.2 本期边界

首版 Web 工作台仅由 Owner 使用；保留现有 Agent + CLI 路径。新工作台不开放自动删除、库内书目自动合并、跨成员私人信息读取、MCP 写工具或无人确认的批量写入。

电子书阅读、家庭交换、通用 Agent 平台、移动端 APK、自动购买记录和复杂调度平台不纳入本规划。模型接入只使用现有配置支持的 OpenAI 兼容接口，不开展模型训练。

### 2.3 用户可见成功标准

- 有明确书名、作者时，条码依赖故障不会阻止保存有效书目与封面。
- 每张照片都有明确去向：关联到候选/最终书目，或记录跳过及原因。
- 确认过的字段不会被外部元数据或后续模型运行静默覆盖。
- M1：重启、刷新、网络超时后可保留进度；结果未知时暂停自动重试，经核对后决定。M3：按持久命令回执恢复，重试不重复创建书目、副本或购买记录。
- 能看出哪些条目需要核对，哪些已经完成，失败发生在哪一步。
- 能用同一测试集比较模型和提示词版本，说明准确率、耗时及成本的统计口径。

## 4. 核心行为与契约

### 4.1 条码能力与降级

复用受保护 `/api/v1/health` 的 `barcode_scan_available` 和 `bookshelf doctor`，不另造公开诊断入口，也不为了批量入库要求额外授予 `members:read`。诊断无权限时显示能力未知；后端服务仍承担最终判断。

| 输入/故障 | 预期行为 |
| --- | --- |
| 明确、有效的手工 ISBN | 继续校验 ISBN，不依赖图片解码结果才能入库 |
| 图片 + 书名，缺 zbar/解码超时/未发现 ISBN | 按书名及作者继续入库，返回有类别的警告 |
| 只有图片，无法解码且没有视觉候选 | 返回需要补充信息的结果，不创建“未知书名” |
| 图片内容损坏、读取失败 | 明确指出图片无效，不以降级为理由掩盖上传错误 |
| 手工 ISBN 校验失败 | 保留 400/422，不静默忽略输入错误 |

扩展响应的 `warnings` 为可选字段，至少区分依赖不可用、超时、未找到条码、元数据缺失；CLI 与报告使用相同错误码。独立识别接口继续如实报告能力故障，入库降级不意味着识别能力正常。

macOS 说明补充本次 Homebrew zbar 加载排障；`~/lib/libzbar.dylib` 属可选环境处置，不由业务代码自动改写用户目录。

### 4.2 字段来源和优先级

显式表达输入来源与确认状态，避免把模型填写的 title 与用户确认的 title 混为一类。兼容现有调用：未提供新字段时保留既有行为；批量脚本对已确认条目显式使用 `prefer_confirmed` 策略，新工作台默认采用此策略。

优先级为：用户确认/编辑值 → 经核验的识别候选 → 外部元数据补空。模型置信度只用于排序和提示，不能单独表示“经核验”。第一阶段“经核验”指人工确认；自动模式的资格由第 4.7 节决定。

- title、subtitle、authors、isbn 分字段处理，保留多作者数组；不用串接作者字符串替代结构化作者。
- 外部结果与确认值不一致时保留确认值，记录外部候选和来源。
- ISBN 校验位正确只证明格式成立，不证明它属于某张封面；ISBN 归属冲突必须核对。
- ISBN 命中已有书而书名/作者明显冲突时，不自动更新或绑定，进入待核对。
- 显式空值、字段未提供和自动补空分别定义；不得把“清空字段”解释为可再次补回。
- 继续保留既有原始输入去重锚点，覆盖 BUG-163、BUG-169、BUG-171 的回归场景。

第一阶段在回执中记录字段来源/冲突，第三阶段存入 ChangeSetItem；本期不迁移全部存量书目的字段来源。

BI-01 同步承接 RES-006：用一组代表性中文书名/ISBN 分别诊断 NLC、Google Books、OpenLibrary，区分无结果、网络/限流、总时限和错误元数据；保留 provider 与链级耗时。`source=manual` 不是“外部请求超时”的充分证据；未经核验的“source 全为 manual”不能作为开发依据。引入新的中文元数据提供方仅列诊断建议，另行评估，不自动扩入本期。

### 4.3 照片、候选书目与最终图书

数据关系为“多张照片 → 一个候选书目 → 一个最终图书”。照片不是新增图书计数单位。

| 对象 | 最少字段/职责 |
| --- | --- |
| 照片条目 | 稳定 photo_id、相对路径、内容 SHA-256、图片角色、候选 ID、结果/警告 |
| 候选书目 | 稳定 candidate_id、关联 photo_ids、书名/副题/作者/ISBN、证据、冲突、核对状态 |
| 执行回执 | run_id、候选版本、command_execution_id、输入摘要、outcome、book_id、时间、错误类别 |
| 最终关联 | 当前 book_id、历史 book_id、修正理由、操作者、来源与时间 |

图片角色支持封面、条码、其他、未知。内容哈希只证明照片相同，不能单凭哈希判断两张不同照片是同一本书。按文件名相邻、书名相似或模型判断推荐配对，均须经核对；书籍版本或卷册不能因相似封面而自动合并。

### 4.4 逐条持久化、运行历史与核对

现行 manifest v1 保持可读；BI-01 冻结 v2 的升级和降级约束。逐条采用临时文件 + 原子替换保存；每次运行产生独立 run_id 和运行报告，另生成批次汇总，避免覆写唯一历史。

保留原始执行回执，最终关联使用独立 reconciliation 记录。`reconcile` 默认只读检查：验证 book_id 是否存在、ISBN 是否冲突、封面引用是否有效。显式应用时只修改清单/报告，不修改生产数据库。

对本批历史修正可使用已核验映射 `10→18`、`11→30`、`12→56`，先确认目标 ISBN，再生成追溯记录。其他批次不得仅按书名自动猜测替代 ID。已删除且找不到可靠目标的条目进入待核对，不能继续显示为已完成关联。

| 报告口径 | 定义 |
| --- | --- |
| 照片总数 | 批次内照片条目数，包含重复与跳过 |
| 单次运行 | 本次创建、已存在、失败、未处理/跳过；重跑不抹去旧报告 |
| 最终关联 | 成功关联的照片数、不同有效 book_id 数、未解决关联数 |
| 批次净新增 | 本批创建且最终仍存活的图书数；关联到原有图书不算新增 |
| 清理/修正 | 临时创建后删除、重映射、字段修正分别统计，不归为新入库成功 |

本次可用作口径样例：71 张照片 → 67 个最终图书；历史曾创建 70 条记录，后删除 3 条，最终净新增 67 本。另有 1 次重复封面命中已有书。不得简单累加重跑的 created 得出批次新增数。

### 4.5 恢复与幂等边界

第一阶段逐条落盘能缩小中断窗口，但客户端保存成功状态与服务器提交之间仍可能断开。仅有书名去重不能承诺副本/购买记录恰好一次；第一阶段对不确定回执先核对再重试，并显式记录该限制。

第三阶段由 CommandExecution 提供稳定幂等键，规范化参数摘要包括候选版本、目标、图片哈希和相关业务参数。同键同参数返回已有回执，同键不同参数拒绝；书目、副本、购买记录和回执在同一事务边界内提交。超时/进程崩溃后按回执查询恢复，不盲目重新发起写入。

状态包括待核对、已确认、执行中、已完成、部分完成、失败、结果未知、已跳过。已确认内容修改后生成新版本并失去原确认资格；恢复时重新鉴权、核验确认版本与资源状态。Worker 租约到期允许接管，旧租约的执行者不得继续提交。

### 4.6 视觉服务与评测入口

统一视觉服务读取 `llm_settings`，支持结构化 title/subtitle/authors/isbn、逐字段可读性、置信度及警告。模型只生成候选，不能直接调用图书写入；无依据字段留空，不补造 ISBN。

第二阶段先交付本机管理 CLI 的评测运行器：显式指定后端数据库配置，由服务内部读取已有模型配置，API Key 不导出给前端/Agent、不写报告。此工具属于受信任的本机运维入口，不是新增远程 Agent 权限。Web 发起完整批次识别安排在第三阶段；避免为评测提前引入完整工作台。

请求处理覆盖禁用/配置缺失、超时、429、非 JSON、字段类型错误、ISBN 校验失败。按图片哈希 + 模型配置指纹 + 提示词版本缓存；重跑命中缓存不再付费调用。鉴权错误不重试；限流/临时错误有次数上限和退避。请求结果未知时注明潜在重复计费，不能承诺外部 API 恰好一次。

接口地址使用 Owner 配置；限制请求超时、图片大小和返回长度，不把图片内容或模型返回的 URL 当作新的任意请求目标。日志排除密钥和请求头。报告记录输入/输出 token（提供方可得时）、耗时、缓存命中和费用；未知价格/usage 时费用标为未知，不填 0。

### 4.7 金标准与自动模式门控

真实金标准需人工逐项核对；现有识别结果只能作为标注草稿。记录图片分组、书名/副题、多作者、ISBN 可见性及难度，区分“封面未署作者”与“模型漏作者”。同一本书的多张照片作为同组划分校准/验收集，避免重复照片泄漏。

复用现有 compare 指标：书名 ≥90%、作者 ≥80%、书级完全正确率 ≥75%；同时补充多作者完整性、ISBN 准确率/解码召回、元数据冲突、人工修正率、端到端耗时和人工核对耗时。现有“任一作者命中”指标保留兼容，不能用它宣称多作者全部正确。

自动模式继续为显式选择，默认人工核对。M2 不因 75% 达标自动启用生产自动入库；达标只代表既有最低评测条件满足。增强门控要求匹配模型配置、提示词、测试集版本和任务类型；样本未核验、样本不足或证据不匹配时拒绝。

试点样本下限建议至少 20 本不同书，并含关键困难类别；71 张照片不是 71 个独立书目样本。低置信度、字段不可读、ISBN 冲突及重复候选歧义均转人工。任何误合并、确认字段静默覆盖或未确认写入用例失败，都阻断发布；不能用总体准确率抵消。

### 4.8 工作台与授权

首版 Owner 流程：上传多图 → 识别进度 → 候选书目核对 → 关联照片/选择重复目标 → 确认选中条目 → 执行 → 查看回执/重试失败。

页面展示图片、候选字段、来源/冲突、重复目标与修改后的最终差异。不确定条目独立筛选；支持逐条确认或对已核对的选中条目批量确认。改字段必须更新候选版本。确认已存在书时默认仅建立照片关联；更新该书字段需另有明确差异确认。

Owner Cookie 写接口校验 CSRF；候选图片走受认证的任务资源读取，不能复用匿名封面入口绕过权限。现有 Agent CLI 只需业务 Scope；模型配置与工作台控制入口不随 `books:write` 开放。合并/删除仍遵守 `books:delete`，本期工作台不发起此类操作。

第三阶段实现最小 WorkItem、AgentRun、ChangeSet/Item、Decision 和 CommandExecution，复用上位规划的版本、预算、租约、权限和审计语义；不建设完整通用编排平台。

首版后台执行定位为 Owner 发起的 Human Workflow：确认决策绑定发起人、确定版本与命令；Worker 使用可核验的受限内部调用证明，不保存、转借 Owner Cookie，也不直接以进程身份取得所有业务权限。BI-12 必须先冻结证明、有效期、租约代次及撤权检查方式；每次执行重新验证 Owner 仍有效且有相应能力，停用/撤权或确认失效后拒绝提交。若后续改用内部 Agent Runner，必须另行冻结 Client/Grant 与版本绑定方案，不能在实现中隐式更换执行主体。
